# СВЕЧА — ДВИЖЕНИЕ: экспериментальный hand-forward режим (23.11.2026)

База: `integration/candle-free-practice-20261121` (Draft PR #6). Это **отдельный, не подключённый к интерфейсу** эксперимент. Работающий Pose остаётся режимом по умолчанию, а BOSH владеет `src/main.js`, `src/style.css` и выбором поведения UI. Нет auto-merge / production.

## Зачем

Владелец показал работающий Pose на GPU, но не хочет отходить от камеры, чтобы держать плечи и корпус в кадре. Google MediaPipe Hand Landmarker даёт 21 точку кисти, не требуя плеч, но **монокулярная камера не может измерить силу удара, реальное продвижение руки по глубине или поток воздуха**. Единственная ладонь/кулак не позволяет надёжно отличить намеренный удар от жеста, поворота кисти или руки другого человека. Поэтому режим должен быть opt-in до проверки живыми людьми.

Источники:
- Официальный API Hand Landmarker: https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker
- Код MediaPipe Web SDK / модель: https://github.com/google-ai-edge/mediapipe/tree/master/mediapipe/tasks/web/vision
- Пин модели Google Hand Landmarker Full FP16 v1: https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task
- SHA-256 `fbc2a30080c3c557093b5ddfc334698132eb341044ccee322ccf8bcf3607cde1`; 7 819 105 байт. Источник независимой записи контрольной суммы: https://github.com/vercel-labs/vgpu/blob/canary/apps/docs/public/models/mediapipe-hands/provenance.md . Скрипт проверяет оба значения **перед** включением файла; здесь загрузка из сети не выполнялась.

## Подготовка и подключение без второго видеопотока

```sh
npm ci
npm run prepare:vision
node scripts/prepare-hand-landmarker-assets.mjs
npm test
npm run build
```

Скрипт подготовки загружает pinned task **при сборке**, проверяет SHA-256, помещает файл в `public/models/hand_landmarker.task`; общий WASM уже локально готовится `prepare:vision`. Во время работы `hand-worker.js` запрашивает модель/WASM исключительно с собственного origin и запрещает внешние fetch/XHR (как существующий Pose). Web worker использует `HandLandmarker.detectForVideo`, `numHands:2` ради обнаружения неоднозначности; сначала GPU, при ошибке инициализации CPU. Поля `ready.initMs` и `diagnostics.inferenceMs` доступны только для **локального** измерения, без выдуманных FPS для Redmi. Не запускать Pose и Hand одновременно: один `PoseTracker` получает альтернативный `workerFactory`, сохраняя getUserMedia/stop/hidden-tab/late-stream защиту.

```js
import { createHandForwardPractice } from "./vision/hand-practice.js";

// Только после явного выбора пользователем и отдельного нажатия запуска.
const practice = createHandForwardPractice({
  video, mirrorX: true, // true, только если превью реально CSS-отражено
  onUpdate: ({ state, strike, response, frame, analysis }) => {
    if (response) candleRenderer.setState(response.flame);
    // НЕТ позовых линий 33 суставов: frame.hands содержит 21 точку кисти.
    // При сомнении показываем нейтральную короткую подсказку.
  },
  onStatus: ({state,initMs,delegate}) => { /* локальная диагностика */ },
});
await practice.start(); // Пользователь сам запросил камеру
practice.pause();       // Останавливает видеотреки и worker
await practice.resume();
practice.stop();
practice.dispose();

// При ошибке hand-worker: dispose(), сообщить об ограничении и предложить
// обычный существующий FreePracticeCameraController только по клику.
// НЕ переключать камеры/модели автоматически и не открывать 2 worker сразу.
```

## Правила детекции и ограничения

- Начало: одна **цельная** кисть, 21 числовая точка, 4 опорные точки внутри экрана, адекватная геометрия ладони. Если 0 или 2 видимые руки — нет события; идентичность человека не устанавливается.
- Условие: увеличение **двух** независимых размеров ладони (поперёк MCP 5–17 и от запястья 0 к MCP 9), минимум два кадра подряд, относительное увеличение масштаба `>= 1.23` и последующее уменьшение `<= 0.94` от пика. Это лишь признак видимого приближения, **не** доказательство удара.
- Устойчивость: нормированный размер (не пиксели/метры), монотонный timestamp, разрыв не более 180 мс, минимальный наблюдаемый FPS 10, ограничение скачка положения/формы, боковой траектории, 650 мс для жеста, 450 мс пауза между событиями; пауза и потеря трекинга сбрасывают частичную траекторию.
- При вращении ладони, окклюзии, скачках, низком FPS, нескольких руках и сомнительной геометрии — `strike:null`, никакого «попадания» и тушения. В SDK нет достоверной независимой оценки видимости каждого сустава — скрытая ладонь может быть **галлюцинирована** моделью. Строгая точность без размеченных данных не заявляется.
- Поля `peakSpeed`, `confidence` — **безразмерный визуальный proxy** и эвристический индикатор согласованности, не физическая скорость, сила, вероятность удара или измерение потока воздуха. `mirrorX` применяется к визуальному направлению, но не к критерию события.
- Память жеста O(1), не сохраняются кадры и индивидуальные траектории. Отдельный существующий экспорт трейсов остаётся явно opt-in и чувствителен.

## Подсказки для единого экрана

- Готовность: «Вижу руку — попробуйте движение к камере и обратно».
- Недостоверно: «Не уверен в движении — попробуйте ещё раз».
- Нет руки: «Покажите кисть в кадре».
- Несколько рук: «Оставьте в кадре одну руку».
- Не требовать от пользователя **видеть на экране плечи**. Никаких этапов, очков, калибровочного мастера.

## Что проверено и что остаётся

Локально выполнены детерминированные тесты чистого `HandForwardAnalyzer`: 100 повторов, зеркальное направление, стабильный кулак, боковые жесты, скачки времени, окклюзия, несколько кистей, пауза — **синтетические PASS**, не real-device evidence. Полный интеграционный npm CI и браузер с реальным WASM/моделью требуется подтвердить GitHub Actions / BOSH. Фактическая инициализация модели, загрузка pinned blob, FPS, задержка, CPU fallback, охват кулака на Redmi Note 9S **не проверены здесь**.

Ручной протокол для QA (только с согласия пользователя, без записи видео):
1. Браузерный preview с включённым hand opt-in на Redmi Note 9S Android 11; 60 секунд камеры и свечи. Фиксировать только локальные initMs, median/p90 inferenceMs, fps, температуру по ощущениям/лаги — не отправлять кадры.
2. 10 раз неподвижный кулак, 10 боковых махов, 10 плавных жестов, 20 контролируемых приближений-возвратов, на двух расстояниях и при слабом свете. Считать **вручную размеченные** TP/FP/FN, отдельно случаи неоднозначности. Повторить со второй рукой.
3. Проверить руку у края кадра, 2 руки/прохожего, поворот ладони, скрытые пальцы, падение FPS и background/stop/permission denied.
4. Проверить CSS mirror: направление огня совпадает с видимым экраном. При недостаточном качестве вывести нейтральное сообщение и оставить безопасную опцию возврата на Pose.
5. Только после реальные данные/скриншот **самой свечи без камеры** и согласование владельца. **Личные изображения и видеокадры не коммитить.**

**Рекомендация BOSH:** сохранить текущий Pose по умолчанию; не включать hand-only для всех до подтверждённого теста на телефоне. Никакой принудительной стойки с плечами в UI, но и обещаний точного hand-only punch detection.
